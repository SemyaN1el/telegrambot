# Telegram-бот для детекции токсичных комментариев

Проект состоит из Telegram-бота на `aiogram`, локально сохранённой модели `RoBERTa` для многометочной классификации токсичности и Jupyter-ноутбука, в котором выполняются исследование данных, обучение и сохранение модели.

Бот принимает текстовые сообщения, пересылает их в чат администратора и возвращает пользователю результат анализа: основной класс и вероятности по всем шести меткам токсичности.

## Что умеет бот

- загружает модель и токенизатор из локальной директории `my_roberta_model`
- работает через long polling
- анализирует входящий текст на CPU
- определяет токсичность по 6 меткам
- показывает вероятности по каждой метке
- считает сообщение корректным, если ни одна вероятность не превышает порог `0.5`
- пересылает входящие сообщения в чат администратора

## Метки классификации

Модель обучена как `multi_label_classification` и использует следующие классы:

| Английская метка | Отображение в боте |
| --- | --- |
| `toxic` | Токсичный |
| `severe_toxic` | Сильно токсичный |
| `obscene` | Непристойный |
| `threat` | Угроза |
| `insult` | Оскорбление |
| `identity_hate` | Ненависть к личности |

Важно: модель многометочная, но бот в ответе показывает один основной класс, выбирая метку с максимальной вероятностью, и дополнительно печатает вероятности по всем классам.

## Как работает бот

1. При запуске `bot.py` читает `.env`.
2. Затем загружает токенизатор и модель из `my_roberta_model`.
3. Имена классов берутся из `config.json`.
4. При получении обычного текстового сообщения бот:
   - пересылает сообщение в `ADMIN_CHAT_ID`
   - приводит текст к нижнему регистру и убирает пробелы по краям
   - токенизирует текст с `max_length=256`
   - применяет модель
   - пропускает логиты через `sigmoid`
   - сравнивает вероятности с порогом `0.5`
5. Если ни одна метка не превысила порог, бот отвечает `Класс: Корректный`.
6. Если хотя бы одна метка превысила порог, бот выбирает метку с максимальной вероятностью как основной класс и выводит полный список вероятностей.

- базовая модель: `roberta`
- число меток: `6`
- тип задачи: `multi_label_classification`

## Что есть в ноутбуке `toxic-class.ipynb`

Ноутбук покрывает полный цикл подготовки модели:

- загрузка датасета Jigsaw Toxic Comment Classification с Kaggle
- базовый EDA и визуализации распределения классов
- анализ длины текстов, частотных слов и выбросов
- очистка и нормализация текста
- токенизация через `AutoTokenizer.from_pretrained("roberta-base")`
- разбиение на train/validation
- обучение `AutoModelForSequenceClassification`
- функция потерь `BCEWithLogitsLoss`
- оптимизатор `AdamW`
- валидация по средней `ROC-AUC`
- early stopping
- сохранение модели в `./my_roberta_model`
- генерация submission-файла для Kaggle

Ключевые параметры, которые явно зафиксированы в ноутбуке:

- `max_length=128` при подготовке данных для обучения
- `BATCH_SIZE=16`
- `EPOCHS=3`
- `LEARNING_RATE=2e-5`
- `patience=2` для early stopping

## Как дообучалась RoBERTa под датасет

Ниже описан фактический пайплайн fine-tuning из ноутбука, без догадок и общих формулировок.

### 1. Датасет

Использовался датасет Kaggle Jigsaw Toxic Comment Classification:

- `train.csv` для обучения
- `test.csv` для инференса и подготовки submission
- `test_labels.csv` загружался вместе с датасетом

Размеры, зафиксированные в ноутбуке:

- обучающих комментариев: `159571`
- тестовых комментариев: `153164`

Целевые метки:

- `toxic`
- `severe_toxic`
- `obscene`
- `threat`
- `insult`
- `identity_hate`

Постановка задачи: многометочная классификация, потому что один комментарий может относиться сразу к нескольким классам.

### 2. Подготовка данных

Перед токенизацией текст проходил функцию `clean_text()` со следующими шагами:

- приведение к нижнему регистру
- удаление URL
- удаление HTML-тегов
- удаление спецсимволов и эмодзи через регулярные выражения
- удаление чисел
- удаление лишних пробелов
- токенизация через `nltk.word_tokenize`
- удаление английских stop words
- лемматизация через `WordNetLemmatizer`
- удаление слишком коротких токенов длиной `<= 2`

После очистки модель обучалась не на исходном `comment_text`, а на поле `cleaned_text`.

### 3. Токенизация

Для токенизации использовался:

- `AutoTokenizer.from_pretrained("roberta-base")`

Параметры токенизации:

- `max_length=128`
- `padding=True`
- `truncation=True`
- `return_tensors="pt"`

Это означает, что длинные комментарии обрезались до 128 токенов, а короткие дополнялись padding до общей длины батча.

### 4. Разделение выборки

Разделение train/validation сделано через `train_test_split`:

- `test_size=0.2`
- `random_state=42`
- `shuffle=True`
- без стратификации

Итоговые размеры:

- train: `127656`
- validation: `31915`

Также в ноутбуке фиксировался seed:

- `seed=42`

Он применялся к `random`, `numpy`, `PYTHONHASHSEED`, `torch` и `torch.cuda`.

### 5. Базовая модель и постановка fine-tuning

В качестве базы использовалась предобученная модель:

- `roberta-base`

Модель создавалась так:

```python
AutoModelForSequenceClassification.from_pretrained(
    "roberta-base",
    num_labels=6,
    problem_type="multi_label_classification"
)
```

Что это означает:

- берётся готовая языковая модель `RoBERTa`
- поверх неё добавляется классификационная голова на 6 выходов
- задача явно помечается как `multi_label_classification`

По логам ноутбука, классификационная голова инициализировалась заново, что нормально для fine-tuning на новой downstream-задаче.

Количество параметров модели:

- `124,650,246`

### 6. Параметры обучения

Обучение запускалось на `cuda`, если GPU был доступен.

Гиперпараметры, явно использованные в ноутбуке:

- `BATCH_SIZE = 16`
- `EPOCHS = 3`
- `LEARNING_RATE = 2e-5`
- `patience = 2` для early stopping
- `gradient clipping = 1.0`

Оптимизация:

- оптимизатор: `AdamW`
- scheduler: `get_linear_schedule_with_warmup`
- warmup: `10%` от общего числа шагов

Функция потерь:

- `BCEWithLogitsLoss`

Это корректный выбор для многометочной классификации, потому что каждая из шести меток предсказывается независимо.

### 7. Что именно подбиралось

В текущем ноутбуке нет отдельного блока с `Grid Search`, `Optuna`, `Random Search` или сравнением большого числа конфигураций. Поэтому корректнее говорить не о полном автоматическом подборе, а о ручном выборе baseline-конфигурации.

По коду видно, что фактически были зафиксированы и использованы такие ключевые параметры:

- выбор базовой архитектуры: `roberta-base`
- постановка задачи: `multi_label_classification`
- длина последовательности: `128`
- размер батча: `16`
- learning rate: `2e-5`
- число эпох: `3`
- early stopping с `patience=2`
- метрика валидации: средняя `ROC-AUC` по всем 6 меткам

Если вам нужен текст именно в стиле "что я подгонял", то честная формулировка для README такая: параметры fine-tuning подбирались вручную на baseline-уровне, а основной контроль качества шёл по `Mean AUC-ROC` на validation.

### 8. Валидация и метрики

На валидации считались:

- `Val Loss`
- `Mean AUC-ROC`
- `AUC-ROC` отдельно по каждому классу

Лучший результат из сохранённых output ноутбука был на 2-й эпохе:

- `Train Loss: 0.0413`
- `Val Loss: 0.0411`
- `Mean AUC-ROC: 0.9869`

По классам:

- `toxic: 0.9832`
- `severe_toxic: 0.9900`
- `obscene: 0.9933`
- `threat: 0.9819`
- `insult: 0.9860`
- `identity_hate: 0.9870`

На 3-й эпохе средняя метрика немного снизилась до `0.9867`, поэтому лучшей осталась модель со 2-й эпохи.

После завершения fine-tuning модель и токенизатор сохранялись в Hugging Face формате:

Именно эти файлы потом используются в [bot.py](C:\Users\SemyaNiEl\PycharmProjects\telegrambot\bot.py) для инференса.

### 10. Важный нюанс между обучением и ботом

В ноутбуке обучение шло с `max_length=128`, а в боте инференс выполняется с `max_length=256`.

Это не ломает модель, но означает, что:

- режим инференса не полностью совпадает с режимом обучения
- при желании можно привести их к одному значению и переоценить качество
- отдельно можно подобрать порог не только глобально, но и по каждому классу

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <repo_url>
cd telegrambot
```

### 2. Если используется Git LFS

```bash
git lfs install
git lfs pull
```

### 3. Создание виртуального окружения

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 4. Установка зависимостей

Для запуска бота:

```bash
pip install -r requirements.txt
```

Для работы с ноутбуком можно дополнительно установить:

```bash
pip install pandas matplotlib seaborn nltk scikit-learn tqdm wordcloud beautifulsoup4 umap-learn kagglehub
```

### 5. Настройка `.env`

Создайте файл `.env` со следующими переменными:

```env
API_TOKEN=your_telegram_bot_token
ADMIN_CHAT_ID=123456789
```

Где:

- `API_TOKEN` - токен Telegram-бота от BotFather
- `ADMIN_CHAT_ID` - ID чата, куда бот будет пересылать входящие сообщения

### 6. Запуск

```bash
python bot.py
```

После запуска бот начнёт polling и будет ждать входящие сообщения.

## Ограничения и особенности

- Бот запускает модель только на CPU: в `bot.py` явно используется `.to("cpu")`.
- Для запуска без Docker всё равно нужно вручную установить зависимости из `requirements.txt`.
- `test.py` не является набором тестов и не проверяет работоспособность проекта автоматически.
- Ноутбук ориентирован на Kaggle-пути вида `/kaggle/input/...`; для локального запуска пути придётся адаптировать.
- В обучении используется многометочная постановка, но интерфейс бота сводит ответ к одному основному классу.
- Если модель не загрузится, бот будет отвечать строкой `Модель недоступна`.
