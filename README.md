# Telegram-бот для детекции токсичных комментариев

Проект состоит из Telegram-бота на `aiogram`, локально сохранённой модели `RoBERTa` для многометочной классификации токсичности и Jupyter-ноутбука, в котором выполняются исследование данных, обучение и сохранение модели.

Бот принимает текстовые сообщения, пересылает их в чат администратора и возвращает пользователю результат анализа: основной класс и вероятности по всем шести меткам токсичности.

## Что умеет бот

- загружает модель и токенизатор из локальной директории `my_roberta_model`
- работает через long polling
- анализирует входящий текст на CPU
- определяет токсичность по 6 меткам
- показывает вероятности по каждой метке
- считает сообщение корректным, если ни одна вероятность не превышает порог `0.5`
- пересылает входящие сообщения в чат администратора

## Метки классификации

Модель обучена как `multi_label_classification` и использует следующие классы:

| Английская метка | Отображение в боте |
| --- | --- |
| `toxic` | Токсичный |
| `severe_toxic` | Сильно токсичный |
| `obscene` | Непристойный |
| `threat` | Угроза |
| `insult` | Оскорбление |
| `identity_hate` | Ненависть к личности |

Важно: модель многометочная, но бот в ответе показывает один основной класс, выбирая метку с максимальной вероятностью, и дополнительно печатает вероятности по всем классам.

### Назначение файлов

- `bot.py` - основной исполняемый файл Telegram-бота.
- `my_roberta_model/` - сохранённая модель Hugging Face и файлы токенизатора.
- `toxic-class.ipynb` - ноутбук с анализом датасета, очисткой текста, обучением `roberta-base`, валидацией и подготовкой submission для Kaggle.
- `test.py` - вспомогательный черновой скрипт для скачивания модели через `kagglehub`; это не автотест.
- `.env` - локальные переменные окружения с токеном бота и ID чата администратора.
- `.gitattributes` - настройка Git LFS для больших файлов модели.

## Как работает бот

1. При запуске `bot.py` читает `.env`.
2. Затем загружает токенизатор и модель из `my_roberta_model`.
3. Имена классов берутся из `config.json`.
4. При получении обычного текстового сообщения бот:
   - пересылает сообщение в `ADMIN_CHAT_ID`
   - приводит текст к нижнему регистру и убирает пробелы по краям
   - токенизирует текст с `max_length=256`
   - применяет модель
   - пропускает логиты через `sigmoid`
   - сравнивает вероятности с порогом `0.5`
5. Если ни одна метка не превысила порог, бот отвечает `Класс: Корректный`.
6. Если хотя бы одна метка превысила порог, бот выбирает метку с максимальной вероятностью как основной класс и выводит полный список вероятностей.

## Модель

По `my_roberta_model/config.json`:

- архитектура: `RobertaForSequenceClassification`
- базовая модель: `roberta`
- число меток: `6`
- тип задачи: `multi_label_classification`
- `transformers_version`: `4.57.1`

Файл весов `model.safetensors` занимает около 500 МБ, поэтому репозиторий рассчитан на использование Git LFS.

## Что есть в ноутбуке `toxic-class.ipynb`

Ноутбук покрывает полный цикл подготовки модели:

- загрузка датасета Jigsaw Toxic Comment Classification с Kaggle
- базовый EDA и визуализации распределения классов
- анализ длины текстов, частотных слов и выбросов
- очистка и нормализация текста
- токенизация через `AutoTokenizer.from_pretrained("roberta-base")`
- разбиение на train/validation
- обучение `AutoModelForSequenceClassification`
- функция потерь `BCEWithLogitsLoss`
- оптимизатор `AdamW`
- валидация по средней `ROC-AUC`
- early stopping
- сохранение модели в `./my_roberta_model`
- генерация submission-файла для Kaggle

Ключевые параметры, которые явно зафиксированы в ноутбуке:

- `max_length=128` при подготовке данных для обучения
- `BATCH_SIZE=16`
- `EPOCHS=3`
- `LEARNING_RATE=2e-5`
- `patience=2` для early stopping

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone <repo_url>
cd telegrambot
```

### 2. Если используется Git LFS

```bash
git lfs install
git lfs pull
```

### 3. Создание виртуального окружения

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### 4. Установка зависимостей

Для запуска бота:

```bash
pip install aiogram torch transformers numpy python-dotenv
```

Для работы с ноутбуком можно дополнительно установить:

```bash
pip install pandas matplotlib seaborn nltk scikit-learn tqdm wordcloud beautifulsoup4 umap-learn kagglehub
```

### 5. Настройка `.env`

Создайте файл `.env` со следующими переменными:

```env
API_TOKEN=your_telegram_bot_token
ADMIN_CHAT_ID=123456789
```

Где:

- `API_TOKEN` - токен Telegram-бота от BotFather
- `ADMIN_CHAT_ID` - ID чата, куда бот будет пересылать входящие сообщения

### 6. Запуск

```bash
python bot.py
```

После запуска бот начнёт polling и будет ждать входящие сообщения.

## Ограничения и особенности

- Бот запускает модель только на CPU: в `bot.py` явно используется `.to("cpu")`.
- В коде нет отдельного файла `requirements.txt`, поэтому зависимости нужно ставить вручную.
- `test.py` не является набором тестов и не проверяет работоспособность проекта автоматически.
- Ноутбук ориентирован на Kaggle-пути вида `/kaggle/input/...`; для локального запуска пути придётся адаптировать.
- В обучении используется многометочная постановка, но интерфейс бота сводит ответ к одному основному классу.
- Если модель не загрузится, бот будет отвечать строкой `Модель недоступна`.
